## 1. 背景与判断

### 1.1 现状证据（2026-09-15 实测）

| 项 | 结果 |
| --- | --- |
| `bash bin/ci-smoke.sh` | 四道闸全绿，exit 0 |
| `mvn verify` | 161 tests，0 fail / 0 error / 0 skip，Checkstyle + JaCoCo 通过 |
| 内置任务 | 5/5 `validate` 通过，suite 5/5 稳定通过 |
| 红队 | 16 DEFENDED / 1 VULNERABLE（等于登记基线 1，本机 Docker 未启动回退非容器 A），门禁自测 7/7 |
| 路线图 Phase 0–4 | 已完成（Phase 4 的 judge 容器 / HTTP judge server 在 `docs/03` §9.3 明确说明不做及原因） |
| 本地 `runs/` 177 个 run 的 `meta.json` | scripted 155、红队 cli 10、测试 cli 10、docker 2；**真实 LLM Agent 0** |

### 1.2 判断

框架内部证据链闭合，但从未被真实 Agent 验证过。`README` / `docs/06` 推荐的小团队路线（smoke → regression、current vs candidate 横评、多轮反馈修正）全部是为真实 Agent 设计的，而接入路径上的关键件仍是桩：`evalsets/_template/scripts/run-agent.sh` 直接 `exit 1`；`--sandbox docker` 默认镜像 `alpine` 跑不了任何 Agent CLI；`history` 把所有 cli Agent 合并成一行看不出版本趋势。

因此本路线的目标不是新阶段功能，而是**把“可用”变成“在用”**：先让真实 Agent 跑起来，再让结果进入团队门禁和团队视野。

## 2. 目标与非目标

### 目标

1. 一个团队能在半天内把自己的 cli / http Agent 接进来并跑出第一份 `suite_report`。
2. Agent 改动进 PR 时能自动跑 smoke 门禁挡退化。
3. 非开发角色（PM / QA / 负责人）能不开终端看懂结果。
4. 每一步都有实跑证据，不新增只在文档里成立的能力。

### 非目标（沿用 `docs/04` §12 与 `research.md` §7）

- 不做带存储 / 账号 / 常驻服务的看板。
- 不做 judge 独立容器、HTTP judge server。
- 不把 `llm_rubric` 升为主判。
- 不做多租户、结果仓库、平台化工作流。
- 不在有真实文档类业务任务之前投入间接 prompt injection 语料。

## 4. 各项设计

### R0 提交待收口改动

现状：`research.md` 重写为加固清单（07-09）、`.agents/skills/ael-analyze-results/` 精简 SKILL.md + 新增 `REFERENCE.md` + `scripts/summarize-suite.sh` / `summarize-run.sh`（07-14）均未提交。脚本已对真实 `runs/suite` 验证可用，`git diff --check` 通过。

方案：按 `ael-verify` 文档-only 闸提交，一次 commit。`.claude/skills` 是到 `.agents/skills` 的符号链接，无需同步。

### R1 真实 Agent 实跑

现状：无任何真实 Agent run。

方案：

- 范围：内置 5 任务 + `evalsets/demo-ops-agent` 2 任务。
- Agent：Claude Code 或 Codex CLI 任一，经 cli 适配器；有条件时再加一个 http 形态的服务 Agent。
- 参数：`suite --repeat 3`，Docker 就绪时加 `--sandbox docker --sandbox-image <R3 镜像>`。
- 产物：`runs/dogfood/` 下的 suite 报告 + 用 `ael-analyze-results` 输出的一份问题清单，落到 `docs/08` 附录或 issue。
- 观察点：`score_trajectory` 是否收敛（反馈是否被利用）、`invalid_submissions` 占比（契约是否好懂）、`status=ERROR` 数量（框架/环境故障）、instructions 是否被 Agent 完整读取、每轮耗时是否落在 `attempt_timeout_minutes` 内。

边界：实跑结果只用于修正路线，不修改任何 hidden 规则去“迎合” Agent；发现任务问题走 `ael-new-task` 正常流程。

### R2 `run-agent.sh` 预设 + 反馈注入

现状：`evalsets/_template/scripts/run-agent.sh` 打印“尚未接入”后 `exit 1`；`agents.yaml` 的 current / candidate 都指向它。cli 适配器已提供 `AEL_INSTRUCTIONS` / `AEL_INBOX` / `AEL_ATTEMPT_ID` / `AEL_FEEDBACK`（上一轮 feedback 文件路径，首轮为空串）等环境变量，但对 `claude -p` 这类每轮新起进程的 Agent，`instructions.md` 只说“反馈会写到某目录”，Agent 未必去读。

方案：

- `run-agent.sh <profile>` 内置三个 profile：`claude`、`codex`、`custom`（占位，明确报错）。
- 统一 prompt 组装：`instructions.md` 全文 + （若 `AEL_FEEDBACK` 非空）“上一轮评审反馈” 段（读该 JSON 的 `feedback` / `failed_checks` / `next_step`，不读其他字段）+ 明确一句“本轮提交文件名为 `$AEL_INBOX/$AEL_ATTEMPT_ID.json`”。
- profile 之间只差最后一行调用命令；模型 / 权限参数通过 `AEL_AGENT_MODEL` 等环境变量覆盖，不写死。
- 模板 `agents.yaml` 的 current / candidate 改为示例 `claude` / `codex` profile，并注释如何换成团队自己的命令。
- `evalset init` 生成的副本随模板更新（`EvalsetInitScaffoldTest` 断言脚本含 profile 分支）。

边界：脚本只读 feedback 的对外字段；不得读取 `judge/`、`hidden/`。脚本不假设网络，模型调用失败要非零退出让框架记为该轮无提交。

### R3 Docker Agent 镜像配方

现状：`--sandbox-image` 描述为“须自带 Agent 命令所需环境”，CI 红队用 `alpine` 固定 digest；仓库没有任何能跑 Agent CLI 的镜像示例。

方案：

- 新增 `docker/agent-cli.Dockerfile`：基于官方 node LTS slim，安装 `@anthropic-ai/claude-code` 与 `@openai/codex`，附 `bash`、`jq`、`curl`；不内置任何凭证。
- 凭证经 `--sandbox-docker-arg '-e ANTHROPIC_API_KEY'` 等透传；文档明确“镜像不含密钥”。
- `README` cli 一节与 `docs/06` 接入一节补一段“构建镜像 → 跑一次 `--sandbox docker`”的标准命令。
- 不改红队 CI 的 alpine 镜像（隔离回归与 Agent 运行环境是两件事）。

边界：`--sandbox-network none` 仍为默认；需要模型 API 时用户显式改 `bridge` 并接受该边界，文档写清。

### R4 `history` / `report` 按 label 归档

现状：`RunMeta.agentName` 取 `adapter.name()`（cli 恒为 `"cli"`），`report.json` 的 `run.agent` 与 `history` 的 `(task_id, agent)` 分组都用它；suite 的 `--label` 只进 `suite_report`。多 label 的 cli Agent 在 `history` 里合并成一行。

方案：

- `RunManager.RunConfig` 增 `label`（可空）；`RunMeta` 增 `agentAdapter`，`agentName` 改为 `label` 非空取 label、否则取 `adapter.name()`。`Jsons` 已 `FAIL_ON_UNKNOWN_PROPERTIES=false`，旧 `meta.json` 缺新字段可读。
- `RUN_STARTED` trace 事件 `agent` 字段同步为 label，另加 `adapter` 字段；同步 trace schema、`TraceLoggerTest`、`OtlpTraceExporterTest`。
- `run` 命令增 `--label`；`suite` 把 `AgentSpec.label` 传入。
- `report.json`：`run.agent` = label，新增 `run.adapter`；`report.md` “Agent / 模型”行展示 label。
- `history`：分组键不变（仍是 `run.agent`），语义自然变为按 label；`--agent` 过滤按 label。
- `ael-analyze-results` 的 REFERENCE.md 删除“history 按 adapter 聚合”口径坑，改为说明旧 run 的兼容表现。

验收：`HistoryCommandTest` 新增“两个 label 不同的 cli run 分成两行”；`ReportGeneratorTest` 断言 `run.agent` / `run.adapter`；`SuiteRunnerTest` 断言下钻 run 的 `meta.json.agent_name` 等于 label。

### R5 evalset CI 工作流模板

现状：`.github/workflows/ci.yml` 只守框架自身。团队 evalset 没有现成的 PR 门禁。

方案：

- 新增 `evalsets/_template/ci/evalset-smoke.yml`（不放 `.github/`，避免在本仓库触发），内容：checkout → JDK 17 → 构建 jar（或下载 release jar）→ `validate` 全部任务 → `suite --tasks-root evalsets/<set>/tasks --tier smoke --agents-file ... --repeat 2 --fail-on-not-passed` → 上传 `suite_report.*`。
- 提供两种变体注释：Agent 在同仓库（直接跑）/ Agent 在另一仓库（用 `repository_dispatch` 或把 evalset 作为子模块）。
- 需要真实模型的 job 默认 `if: github.event_name == 'workflow_dispatch'`，避免每个 PR 花钱；smoke 的 scripted 基线行永远跑。
- Docker 强制项按 `ci.yml` 的 `redteam-docker-enforced` 写法给注释示例。
- `evalset init` 一并复制该文件；`docs/06` “推荐门禁”一节指向它。

边界：模板里不出现任何密钥；模型凭证只通过 `secrets.*` 引用示例。

### R6 自包含 HTML 报告

现状：`suite_report` / `report` / `history` 各有 `.json` + `.md`。`docs/05-交互式导览.html` 已是零依赖单文件先例。

方案：

- 形态：与 `.md` 同处生成 `.html`，把对应 JSON 内联为 `<script type="application/json">`，页面 JS 只做渲染，无外链、无 CDN。
- `suite_report.html`：模式识别（single / comparison）、任务 × Agent 矩阵（pass^k 着色）、`risk_summary` / 失败规则热点、每格链接到相对路径的 `report.html`。
- `report.html`：`run` 摘要、`score_trajectory` 折线、`best_attempt.dimension_breakdown`、逐 attempt 的 `failed_rules` 与对外 feedback、`tool_usage` / `safety` / `cost` 三栏。
- `history.html`：`trends` 表 + 每 `(task, agent)` 的分数走势。
- 实现落点：`report/HtmlRenderer`（纯函数 JSON → HTML 字符串，模板放 `src/main/resources/report/*.html`），由 `ReportGenerator` / `SuiteRunner` / `HistoryCommand` 各调一次。

边界：

- 只读三份公开 JSON；不读 `judge/*.judge.json`（`private_notes` 含 expected）、不读 `hidden/`。
- 不新增数据字段，HTML 是 JSON 的视图；测试只断言文件存在、内联 JSON 与 `.json` 文件一致、关键字段字符串出现。
- 不做服务端（`agent-eval ui`）；如日后需要常驻浏览，再评估。

### R7 第一批业务 smoke 任务

现状：内置 5 任务为通用能力题；`evalsets/demo-ops-agent` 是演示集。

方案：团队侧工作，框架侧只保证路径通畅：`ael-build-evalset` → `ael-new-task` 生成 5 个任务 → `ael-review-task-quality` 审查 → 每个任务 scripted fail→pass 闭环 + 真实 Agent 至少一次 run。以 `docs/07` 为质量门槛，`tier: smoke`。

### R8 `PENDING_HUMAN` 处置流程

现状：`RunStatus.PENDING_HUMAN` 在 Agent 提交 `needs_human_review:true` 时产生，`report.md` 有“人工复核请求”一行；suite 如何对待、人工确认后如何放行、是否计入 pass_rate 均无文档。

方案：

- 先定语义：`PENDING_HUMAN` 在 suite 中算“未稳定通过”并单列进 `risk_summary.pending_human_tasks`；不自动转 PASSED。
- 提供 `agent-eval judge --task ... --submission <inbox>` 作为人工复核后的离线重判入口（已存在），文档写清复核人如何记录结论（run 目录下 `review/decision.json`，不改原 report）。
- `docs/06` “看报告”表增一行；`suite_report.md` 小团队操作摘要增一项。

边界：不引入审批流、不引入账号；决策文件只是留痕。

### R9 文档口径与测试缺口收尾

## 附录 A：R1 实跑记录（2026-09-15/16）

### A.1 环境与范围

- Agent：Codex CLI 0.154.0，模型 `gpt-5.6-sol`（自定义 provider，`model_reasoning_effort=max`），经 `run-agent.sh codex` 预设接入。
- 宿主直跑：内置 5 任务 × 3 次（`prd-review-001` 与 `tool-call-001` 因见下问题各只完成 1 次后中止）+ `demo-ops-agent` 2 任务 × 1 次。
- Docker 沙箱：`api-payload-001` × 1（`ael-agent-cli` 镜像，`--sandbox-network bridge`，codex provider 配置只读挂载）。
- 产物：`runs/dogfood/`、`runs/dogfood-docker/`（不入库）。

### A.2 结果

| 任务 | run 数 | 结果 | 说明 |
| --- | --- | --- | --- |
| api-payload-001 | 3（宿主）+ 1（Docker） | 85 / 85 / 70-FAILED；Docker 70→85 PASSED | pass^3 抓出不稳定（第 3 次两轮提交写错位置）。三次都挂 `EVIDENCE_VALID`，事后确认是 judge 契约缺陷（A.3-9），修复后离线重判为 100。Docker 里第 2 轮按反馈修正到 85，多轮反馈注入有效 |
| code-fix-001 | 3 | 100 / 92.5 / 92.5 全 PASSED | Agent 能在 workspace-write 沙箱里编译运行；耗时 4–10 min |
| doc-analysis-001 | 3 | 100 × 3 | 稳定 |
| prd-review-001 | 1 | FAILED，三轮均 5 min 超时无提交 | 见 A.3-6 |
| tool-call-001 | 2 | 第 1 次 FAILED（三轮超时）；修复后第 2 次 90 PASSED，`user.lookup` + `card.create` 各 1 次可信调用 | 见 A.3-3 / A.3-4 |
| log-triage-001 | 2 | 100 × 2 | 稳定 |
| config-audit-001 | 1 | 100 | 稳定 |

观察点结论：

- `score_trajectory` 收敛性：有反馈的轮次都在上行（70→85），反馈可被利用。
- `invalid_submissions`：15 个宿主 run 里 5 个出现无效轮，全部是"没写到 inbox"而不是 schema 错——接入问题多于契约问题。
- `status=ERROR`：0。框架无故障。
- 耗时 vs `attempt_timeout_minutes`：生成型长任务（prd-review、tool-call 首次）在 max 推理强度下 5 分钟不够。
- 题面阅读：Agent 日志显示均完整读取 `instructions.md`，并能主动查 `env | rg AEL`。

### A.3 发现与处置

| # | 发现 | 归类 | 处置 |
| --- | --- | --- | --- |
| 1 | `codex exec` 在 stdin 非 TTY 时读到 EOF 才开工，框架子进程 stdin 是一直挂着的管道 → 三轮各等到 5 min 超时 | 框架 | 已修：`AgentProcess` 启动后立即关闭子进程 stdin（`AgentProcessTest`） |
| 2 | Agent 把提交写到 `workspace/inbox/attempt_001.json` 并宣称"已提交"——反馈 `next_step` 写的是相对路径 `inbox/attempt_002.json`，Agent 按 cwd 解析 | 框架 / 反馈文案 | 已修：`next_step` 给绝对路径；无提交时点名 workspace 内错位同名文件并给正确路径（`FeedbackPolicyTest`、`MisplacedSubmissionFeedbackTest`） |
